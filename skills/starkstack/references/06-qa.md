# Phase 6 — QA

**Role:** skeptical QA lead. Assumes it's broken until shown otherwise.

## 1. Test plan
- Every acceptance criterion in `spec.md` becomes at least one case.
- Add these edge cases:
  - empty, max-length and unicode/RTL input
  - concurrent edits and double submit
  - slow or offline network
  - expired session
  - wrong role
  - timezone and DST boundaries
  - pagination edges

## 2. Automated suites
- Run unit and integration tests.
- Add Playwright end-to-end tests for the top 3–5 user journeys (signup or
  login, the core action, payment).
- Run each new end-to-end test 3 times to catch flakiness.

## 3. Real-interface pass (use a browser tool if one is available)
Open the local or preview URL and actually use the app.

- Console errors and failed network requests (4xx/5xx)
- Layouts at 375, 768 and 1440 px
- Keyboard-only navigation and visible focus
- Form validation messages
- Back/forward and deep links, every internal link (no 404s)
- For APIs: curl each route with good, bad and unauthenticated requests
- For CLIs: run `--help`, the happy path and bad flags

Capture screenshots and response bodies as evidence.

## 4. Non-functional checks
- **Performance:** Core Web Vitals (LCP < 2.5 s, INP < 200 ms, CLS < 0.1),
  bundle size, API p95 latency on hot paths. Compare against the baseline in
  `.starkstack/benchmarks.json` if it exists.
- **Accessibility:** labels, contrast, alt text, ARIA only where needed.
- **Resilience:** what users see when a dependency fails (DB, LLM,
  third-party API).

## 5. Make it repeatable: a verify-app skill
If the project doesn't have one yet, write `.claude/skills/verify-<app>/SKILL.md`.
It should cover:

- how to launch the app
- the health check
- how to drive the key flows
- what evidence to capture
- cleanup

Run it once to prove it works. Future runs and other agents reuse it.

## 6. Bugs
- Log bugs in `.starkstack/qa-report.md` (`assets/qa-report.md`).
- If autonomy allows, also open a GitHub issue: `gh issue create --label bug,P1`.
- Send each P0/P1 back to its owning agent with a failing test that
  reproduces it. Re-run QA after the fix.

**Severity:**

- **P0:** data loss, crash, or the core flow is blocked
- **P1:** wrong results, or the core flow is broken for some users
- **P2:** degraded, but a workaround exists
- **P3:** cosmetic

Every bug report includes:

- steps
- expected vs actual
- evidence
- owner
- regression test
- an **"In plain words"** line

## Gate
No open P0/P1. The report lists what was tested, pass/fail counts, bugs by
severity and **what was not tested**.
